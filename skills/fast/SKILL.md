# Fast

Implement what they asked. Do not verify. Finish by opening the ports they need to test. If you hit a bug and don't know why: use the debug skill.

## Engineer

Question only the path of this change, not the product. Fight to add nothing. Delete only what sits on that path. Then the smallest change that does the job. Quality, never quantity. Same result with less code is the win, or better.

Settle the data shape before writing logic. One rule in one place, not scattered checks. If a new need belongs in the core, redesign for it. Do not bolt on. Flatten anything a reader must chase through many files.

Trace to the real cause; do not hide a problem. Proceed on reversible work. Ask only when it cannot be undone or the intent is genuinely unclear.
